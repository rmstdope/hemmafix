## A one-column migration made the review packet too large to paste into the reviewer's prompt

**What happened.** `review-packet hf-998 141` printed 120 KB, of which about 96 KB was the diff of
the generated `drizzle/meta/0019_snapshot.json`. `produce-bead` *The review loop* says to paste the
output whole into the sub-agent's prompt; that meant reproducing it by hand in a tool call, so the
reviewer was instead told to read the unedited file.
**Why.** drizzle-kit writes the whole schema into a new snapshot for every migration, and
`review-packet` includes every changed file's diff.
**Cost.** One rule not followed as written, and roughly three quarters of the packet spent on a
generated file in every review of a migration.
**Prevent by.** `produce-bead` *The review loop* saying how to hand over a packet too large to paste
(the file path is enough), or `.cerebro/cerebro/scripts/review-packet` naming generated files such as
`drizzle/meta/*_snapshot.json` among the changed files without their diff.
**Seen before.** none found.

## A parked, green-but-for-one-flake pull request went into conflict and met a second copy of the list order

- **Implementer:** Storm (resuming Cyclops's pull request)
- **Date:** 2026-11-27

**What happened.** The e2e job failed on `jul.spec.ts:170`, flaky and not reproducible locally, so the
bead was parked for the navigator. By the time it was unparked, hf-pkn had merged: `board-tabs.ts`
conflicted, `moveTask` re-sorted the browser's list by creation time (losing this bead's order of the
undated, with no conflict and no failing test), and `postpone.spec.ts` expected undated last.
**Why.** The flake was a real app bug (hf-o84). hf-pkn repeats `listOpenInstances`'s order in
`src/lib/postpone.ts`, so a change to the query does not reach it.
**Cost.** One park, a rebase, a second full local gate and a follow-up review. The one granted re-run
was moot: a conflicting head needs a new CI run anyway.
**Prevent by.** A comment or test at `listOpenInstances` naming `byListOrder` as its copy, so that
whoever changes the order changes both.
**Seen before.** none found.

## A conflict resolution was committed with the syntax error it was being tested for

**What happened.** The resolution of `board-tabs.ts` left a stray brace. The test run that showed it
was piped through `tail` inside an `&&` chain, so `git rebase --continue` ran anyway; the fix then
stayed uncommitted while the gate passed on the working tree.
**Why.** A pipe hid the exit status (the root `CLAUDE.md` warns of this), and the gate does not check
that the tree is clean.
**Cost.** One extra commit, rebase and gate run; caught before any push.
**Prevent by.** `produce-bead` *Building* requiring `git status --porcelain` to be empty when the
gate starts.
**Seen before.** none found.
